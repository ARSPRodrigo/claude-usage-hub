## v0.4.5-beta

### Action required

Collectors installed before this release must be reinstalled to pick up the
data-loss fix below. Existing installs keep running, but will continue to
discard usage permanently if their API key ever stops working.

### Fixed

**Collector no longer destroys usage data when an upload is rejected**

The collector commits its file cursors and dedup hashes *before* attempting an
upload, so the outbox is the only thing preventing data loss. Rejected uploads
(4xx) returned early without ever being queued — only network and 5xx failures
reached the outbox. A collector running with a bad or missing API key would
therefore scan every file, advance its cursors to end-of-file, mark every entry
as seen, and drop the payload. That usage could never be reported again, and
`status` showed the tell-tale `Outbox: 0 pending / Last upload: never` while
usage files sat clearly present on disk. 401/403/408/429 are now queued to the
outbox so the data survives until the key is fixed or the rate limit clears.

**Windows install scripts failed when piped to Invoke-Expression**

`install.ps1` and `migrate.ps1` were served with a UTF-8 BOM, added originally
so PowerShell 5.1 would decode them as UTF-8 rather than CP1252. The BOM stops
`#` from being the first character of line 1, so PowerShell parsed the header
comment as code and the script died before anything ran. Both scripts are now
pure ASCII, which removes the need for the BOM. File-based installs
(`-OutFile` + `-File`, as generated by the Profile page) were never affected.

**API key table offered a copy button that copied an unusable value**

The button beside each existing key copied only the key *prefix*, not the
secret. Pasting it into the installer produced a key that always failed
authentication. Full keys are shown once at generation; lost keys must be
regenerated.

**Invite accept page showed a spurious "Failed to load configuration"**

`useGoogleScript()` returns `{ loaded, error }`, but the page tested the object
itself for truthiness, so the effect ran before Google's script was ready.

**collector.exe download is validated before use**

`install.ps1` now checks the Windows PE magic bytes and file size, falling back
to `collector.js` instead of installing a truncated or placeholder binary.

**Dashboard served stale HTML for missing asset URLs**

The SPA fallback is now sent with `Cache-Control: no-store`, and content-hashed
assets with `immutable`, so a CDN can no longer cache an HTML response against
a JavaScript URL.

**Platform Admin invitations no longer require a workspace selection**

### Added

**`ALLOWED_DOMAIN` accepts multiple domains**

Comma-separated, for organisations signing in from more than one Google domain.
